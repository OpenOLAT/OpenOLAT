Colours

The chooser palette of OpenOlat: 14 hues, 10 steps each. The values come from $o-palette in themes/light/_palette.scss (palette v2, spec OO-colors 3.5). The theme emits each value as a CSS custom property --o-{hue}-{step} on :root in theme.css and content.css, not in email.css. Java reads the same values from the custom properties in the selected theme's theme.css, fallback light.

Theme colours: in addition to the 14 hues, a theme defines its brand colours in $o-theme-colors (default $brand-primary, themes/light/_palette_theme.scss). The compile generates 10 steps per colour and emits --o-theme{n}-{step}, --o-theme{n} (the solid fill) and .o_swatch_theme{n}. The choosers show them as "Theme 1" … "Theme n" after the 14 hues. Java returns only the theme colours the theme defines (Palette.getThemeColors()). The openolat theme defines 4: Sea, Peach, Berry, Sprout. Needs Dart Sass 1.79.0 or later.

All contrast ratios on this page are computed in the browser from the custom properties of the selected theme (WCAG 2 relative luminance). A ratio below the threshold is marked red: 4.5:1 for text, 3:1 for borders on white.

Token layers: the palette primitives on this page belong to the base layer, the first of three layers. The base layer also holds the semantic tokens that give a colour its meaning (--o-text, --o-primary), the 8 status states as --o-state-{state}-{role} and the global elements (buttons, content text and headings). The framework layer holds the colours of layout and generic UI elements (--o-navbar-bg, --o-tree-link), the component layer the colours of the elements of one feature module (--o-coursesite-start-bg, --o-qti-menu-link). Modules read the tokens with var(--o-*), see section Colour Tokens. The states are live on the page Feedback & Status, section "Semantic States". Rules: doc/openolat-frontend.md, chapter 26.

The selected theme CSS has no --o-{hue}-{step} properties. Compile the theme with compiletheme.sh.

Palette primitives

Steps 50 to 400 are tints, their text colour is the step 900 of the hue. Steps 500 to 900 are shades, their text colour is white. Each cell shows the hex value and the contrast of that text colour on the step. Bright hues (yellow, orange, lime, green, cyan) use step 400 as solid fill, deep hues use step 500.

--o-{hue}-{step} $o-palette o-palette($hue, $step) $o-palette-bright

Neutral scale

The greys of the theme: 18 steps from 0 (white) to 1000 (black), from $o-neutral in themes/light/_palette_neutral.scss. The default steps are tinted with slate (OKLCH hue 260, chroma 0.038). Steps 50 to 900 have the luminance of the palette steps. The anchors 25, 150, 250, 750 and 950 keep the light colours of --o-bg-subtle, --o-border, --o-border-strong, --o-text and the shadow colour. Step 450 is the lightest grey with 3:1 on white. A theme config changes the tint with $o-neutral-hue and $o-neutral-chroma (0 gives pure greys); the lightness of each step stays. The choosers do not offer the neutral scale, and the modules do not read a step directly: a semantic or element token reads it. Each cell shows the hex value and the contrast on white.

--o-neutral-{step} $o-neutral o-neutral($step) $o-neutral-hue $o-neutral-chroma

Swatches

Swatch roles per hue

The class o_swatch_{hue} sets the role tokens of one hue. Components read the tokens and never a hex value. The foregrounds are selected at compile time with o-on-color(), the build stops when a pair has less than 4.5:1. The modifiers o_swatch_tint (step 300) and o_swatch_dark (step 500 for bright hues, 700 for deep hues) replace --o-sw-bg, --o-sw-fg and --o-sw-border. The classes set only custom properties, no colours.

o_swatch_{hue} o_swatch_dark o_swatch_tint o_swatch_light --o-sw-bg --o-sw-fg --o-sw-border --o-sw-soft-bg --o-sw-soft-fg --o-sw-soft-border --o-sw-text

Colour Tokens

The tokens of the three layers base, framework and component (OO-9994, OO-10043). modules/_tokens.scss emits all tokens on :root in theme.css, content.css and oo-docs.css, not in email.css. Literal colours exist only in the palette and in the shade tokens: the palette steps, --o-white, the base colours --o-base-{name} and the 150 shade tokens. The base colours carry the colour inputs of the theme 1:1 ($text-color, $brand-primary, $link-color, …). Every semantic token is a var() reference: to its base colour, or to the palette step of its state. An element token reads another token, a palette step or its base colour --o-base-{name}. The modules read the tokens with var(--o-*) (OO-10043).

A client theme overrides a token with the map $o-tokens in its config. The value is the name of any other token ("primary", "tree-link"), a palette step "{hue}-{step}", "white" or a colour. The compile stops for an unknown token or step, for a loop of references and for an override that breaks a contrast pair. Values and ratios below are read from the selected theme.

Semantic tokens

"Reads" shows the declared value in the theme CSS, "Value" the resolved colour. The ratio is the contrast pair the compile checks for an override. The compile also checks text on bg-hover, bg-selected and bg-raised (4.5:1). shadow-color, backdrop and scrim are opaque colours: a rule sets the transparency with color-mix(in srgb, var(--o-backdrop) 50%, transparent).

Element tokens

471 colours of single elements in three layers (modules/_tokens.scss): the global elements of the base layer ($o-token-layer-base, 50), the framework elements ($o-token-layer-framework, 215) and the elements of one feature module ($o-token-layer-component, 208). "Default" shows one of two forms. A Sass default (324 tokens) feeds the token, so a client theme that sets the Sass variable keeps working: the token reads the first token of its list whose default has the same colour, else the palette step with the same colour, else its base colour --o-base-{name}. For 36 tokens the default is a Sass expression: the text colour that o-a11y-color() adjusts for the background of one rule (also for a pressed fill or the navigation bar), a fill that o-a11y-color() adjusts for its text, a text or a mark adjusted for the darkest of the page background, the striped and the hovered table row (selectus-rating-b-text, selectus-rating-c-text, selectus-rating-b-marker, decision D26), the text of a state while the Sass variable has its default, the text of a hover or pressed state on its fill (o-contrast-shade-text(), decision D13), or a computed fill. For 46 tokens it is a fixed colour without a Sass variable: a palette step (rating-star) or a literal colour (since decision D29 the colours of today of otp-*, selectus-status-*, recorder-* and more). A token name in quotes (149 tokens) is a reference to another token: "primary" gives var(--o-primary). There is no Sass variable for it; a client theme sets it with $o-tokens. The ratio is the contrast pair the compile checks for an override.

$o-token-layer-base $o-token-layer-framework $o-token-layer-component --o-{element}-{part} --o-base-{name}

Shade tokens

150 darker or lighter colours of an element token, a semantic token or a state token ($o-token-shades in modules/_tokens.scss): 52 for the hover, focus and active state of 13 buttons, 98 for the colour maths of the modules and for the state mixins of modules/_state_variant.scss (hover, active, edge, tint, gradient stop). 53 are in the base layer, 55 in the framework layer, 42 in the component layer. The name is the token name and a suffix: -hover, -active, -focus for a state, -edge for a darker edge around a fill, -tint for a lighter surface, -stop-{n} for a gradient stop. The compile computes a shade token from its token with darken(), lighten() or adjust-hue() and emits a literal colour. The active fill of a button is 17% darker, 16% for a bright fill with dark text (o-token-active-percent()). The hover and active fills of the light buttons and the table filters are at most 10% and 17% darker: o-contrast-shade-amount() (_functions.scss) takes the largest amount at which the text keeps 4.5:1 (decision D9). The smallest amount is 3%: when no amount from 3% passes, the fill keeps 10% and 17% and the text tokens -fg-hover and -fg-active get the text adjusted for the fill (o-contrast-shade-text(), decision D13). A fill that cannot get darker (black) gets lighter by the same amount (shade function "state", o-contrast-shade(), decision D20). The compile stops when one of these 8 fills has the colour of the normal fill. A shade token follows an override of its token. The map $o-tokens overrides a shade token like an element token. The mixin button-variant (modules/_button_variant.scss) reads the shade tokens for the hover, focus and active state. The compile checks the text of a button, a tag, a label or a toggle on its shade tokens (4.5:1) when an override changes one of the colours. A translucent colour is no token: the rule writes color-mix(in srgb, var(--o-focus) 15%, transparent) for rgba($input-border-focus, 0.15).

$o-token-shades --o-{element}-bg-hover --o-{element}-bg-active --o-{element}-border-hover --o-{element}-border-focus --o-{token}-edge --o-{token}-tint
