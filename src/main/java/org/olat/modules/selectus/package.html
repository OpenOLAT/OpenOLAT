Selectus: recruiting tool

Selectus manages job positions, the applications to these positions and their review by a committee. Applicants apply through public URLs. Staff members, committee members, referees and external reviewers work in their own sites inside OpenOlat.

Main classes

  • {@link org.olat.modules.selectus.RecruitingModule}: the module. It reads the selectus.* and recruiting.* keys of olat.properties.
  • {@link org.olat.modules.selectus.RecruitingService}: the central service for positions, applications, committees and documents. {@link org.olat.modules.selectus.manager.RecruitingFrontendManagerImpl} implements it.
  • Further services with implementations in manager: AssignmentService, SelectusReviewService, FeedbackService, CommentService, TaggingService, MailService, AuditService, AnonymiseService.
  • {@link org.olat.modules.selectus.DocumentEnum}, DocumentType, DocumentOption: the documents an applicant can upload.
  • {@link org.olat.modules.selectus.ApplicationStatus}: the status of an application.

Packages

  • model: JPA entities. The tables start with o_selectus_, for example o_selectus_position, o_selectus_application, o_selectus_attachment, o_selectus_assignment, o_selectus_reference, o_selectus_audit_log.
  • manager: DAOs (for example PositionDAO, ApplicationDAO, ReferenceDAO), service implementations and the jobs. manager.spi holds the decision rubric providers (DecisionRubricSPI: five stars, 1 to 6, 1 to 10, minus/plus, text).
  • dispatcher: public entry points. PositionDispatcher serves /apply, /position, /positions and /positiondetails/. ReferenceDispatcher serves /review/ and /reference/, RefereeDashboardDispatcher serves /refereedashboard/, PublicFeedbackDispatcher serves /publicfeedback/. The mapping is in core/dispatcher/_spring/dispatcherContext.xml.
  • site: the sites SelectusSite, ApplicationSite, ReferenceSite, PublicFeedbackSite and the context entry creators for business paths.
  • pdf: PDFMergeUtility and PDFUtility merge the documents of an application into one PDF.
  • ui: the controllers. RecruitingMainController and PositionListController are the entry points for staff and committee. PositionController shows one position with its applications and committee (ui.committee.list.PositionCommitteeController). ui.app_wizard holds the steps of the application wizard. ui.position edits a position (PositionEditController). Other sub-packages cover committee assignment, reviews, references, decisions, feedback, mail, reports, notifications and the administration (ui.admin.SelectusAdminController).

Jobs

_spring/selectusContext.xml defines the Quartz jobs: CloseStatusJob changes the status of positions every minute, CloseReferencesStatusJob closes due references and public feedback every two hours, and EmailNotificationJob sends the notification mails (recruiting.notification.cronjob.expression, default 0 25 */2 * * ?). The same file registers the extensions of the sites and tools.

Configuration

  • selectus.enabled (default false) switches the module on.
  • selectus.module.available (default false) makes the module available on the instance. RecruitingModule.isEnabled() is true only when this key and selectus.enabled are both true.
  • selectus.positions.login (default false) shows a link to the online submissions on the login page. The administration switches it in SelectusAdminController.
  • recruiting.officeMail, recruiting.adminMail, recruiting.staffMail, recruiting.bcc.staffMail: mail addresses.
  • recruiting.position.status: the position states in use.
  • Tool switches: recruiting.decision.tool, recruiting.tagging.tool (and .system, .position, .administrative), recruiting.notifications.tool, recruiting.rating.abstention, recruiting.rejection.all.decision.
  • recruiting.notifications.head, .secretary, .committee, .exofficio: the events each role is notified about.

The defaults are in olat.properties, except for selectus.module.available and selectus.positions.login: olat.properties does not declare them, so an instance sets them in olat.local.properties. The administration changes the values at runtime through RecruitingModule.
