The colour tokens a module reads. Every sample on this tab uses the custom property var(--o-...) of the current theme. The values and the contrast ratios are measured in the browser. "Reads in this theme" follows the var() references of the theme CSS to the literal colour: a theme that overrides a token shows the new chain. The tokens are defined in themes/light/modules/_tokens.scss, the rules in doc/openolat-frontend.md, chapter 26.

How to use

  • A rule in a module reads a token: color: var(--o-text-muted);, border: 1px solid var(--o-border);, background-color: var(--o-bg-subtle);.
  • Never write a hex value or a Sass colour variable ($text-color, $gray-light, $brand-primary) in a module rule. ThemeColorRatchetTest counts them.
  • Never read a neutral step or a palette step in a rule. A token reads the step.
  • A translucent colour mixes the token with transparent: color-mix(in srgb, var(--o-shadow-color) 15%, transparent).
  • A new customisation point is a new element token in the map of its layer, with a reference to an existing token as default: "my-element-border": "border".
  • A theme changes a token in its config, before the import of the light theme. The value is another token, a neutral or palette step, "white" or a colour: $o-tokens: ("text-muted": "neutral-600", "toolbar-link": "link");

Semantic tokens

The meaning of a colour: text, link, brand, surface, line, overlay and focus. Each semantic token reads its base colour --o-base-{name}, and the base colour carries the Sass variable of the theme config. A dark mode redefines these tokens. Use them for every colour that is not a status and not a single element. Under the value, "= neutral-{step}" names the step of the neutral scale (tab "Palette") with the same colour in the current theme. The contrast under a sample is measured on the sample; "needs" names the ratio the colour must reach (4.5:1 text, 3:1 focus and control borders).

State tokens

The colours of the 8 semantic states ($o-states, see the tab "Badges / Status") as --o-state-{state}-{role}, for a status without a label: icon, marker, progress bar, chart. Roles: text text and icons on white, bg fill, fg text on the fill, border border and chart line, soft-bg, soft-fg and soft-border the tinted block. Each cell shows the token colour and its value; the samples combine the roles and show the measured contrast.

Framework tokens (selection)

The element tokens a module author reuses: the buttons of the base layer and the generic elements of the framework layer. "Default in _tokens.scss" is the default of the map: a Sass variable of the theme config (the token follows the named token while the colours are equal), a reference "token", or a shade, the darker colour of a token computed at compile time. "Reads in this theme" shows which token to override: an override of nav-link reaches toolbar-link and tree-link as long as they read it. The full list is in $o-token-layer-base, $o-token-layer-framework and $o-token-shades.
